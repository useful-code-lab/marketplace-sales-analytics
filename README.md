# Marketplace Sales Analytics & Fraud Detection Pipeline

Практический аналитический pipeline на **Python и Pandas**, который показывает, как превратить сырые и проблемные данные маркетплейса в готовую бизнес-аналитику.

Проект будет полезен разработчикам, аналитикам и тем, кто изучает **Pandas, обработку данных и построение ETL/аналитических pipeline**. Здесь можно посмотреть готовый пример полного цикла: генерация «грязных» данных → очистка → оптимизация → анализ клиентов → поиск аномалий → визуализация → формирование отчетов.

## 🎯 Что можно получить из проекта

Репозиторий можно использовать как практический пример для изучения того, как строить обработку данных не на отдельных ноутбуках, а в виде **структурированного Python-проекта**.

Из проекта можно взять готовые подходы для:

* очистки реальных наборов данных с пропусками, дубликатами и некорректными значениями;
* уменьшения потребления RAM при работе с большими DataFrame;
* построения повторяемого pipeline обработки данных;
* сегментации клиентов с помощью **RFM-анализа**;
* поиска подозрительных операций статистическими методами;
* подготовки CSV-отчетов для дальнейшего анализа;
* автоматической генерации графиков;
* добавления логирования в аналитические скрипты;
* покрытия критической бизнес-логики тестами;
* организации небольшого Data Engineering / Data Analytics проекта на Python.

Главная практическая идея — показать, **как из необработанного CSV получить структурированные данные и понятные бизнес-результаты одним запускаемым конвейером**.

---

## 🔎 Какую задачу решает проект

Представим, что у нас есть выгрузка заказов маркетплейса. В ней могут встречаться:

* пропущенные значения;
* дубликаты заказов;
* некорректные даты;
* различные типы данных;
* большое количество строк;
* необычные значения стоимости заказов;
* транзакции, которые требуют дополнительной проверки.

Вместо ручной обработки проект автоматически проходит несколько этапов:

```text
Сырые данные
     ↓
Очистка и нормализация
     ↓
Оптимизация DataFrame
     ↓
Анализ продаж
     ↓
RFM-сегментация клиентов
     ↓
Поиск аномальных операций
     ↓
Визуализация
     ↓
CSV-отчеты + логирование
```

Таким образом, репозиторий демонстрирует не отдельный прием Pandas, а **целостный сценарий обработки аналитических данных**.

## 🚀 Основные возможности

### 1. Генерация тестовых данных

`generator.py` создает искусственный набор заказов, имитирующий данные реального проекта.

В данные специально добавляются проблемы:

* пропуски;
* дубликаты;
* некорректные даты;
* различные значения и категории;
* аномальные транзакции.

Это позволяет запускать pipeline на данных, похожих на реальные, и проверять устойчивость обработки.

```bash
python generator.py
```

---

### 2. Очистка и подготовка данных

Pipeline автоматически выполняет предварительную обработку данных.

В проекте показаны практические приемы:

* удаление дубликатов;
* обработка пропусков;
* нормализация дат;
* преобразование типов;
* заполнение отсутствующих значений;
* подготовка данных к дальнейшей аналитике.

Особенно полезен подход с заполнением пропусков с учетом категории товара, когда вместо одного общего значения используется статистика соответствующей группы.

---

### 3. Оптимизация потребления памяти

Проект демонстрирует **downcasting типов Pandas**.

Например, типы числовых столбцов приводятся к минимально необходимому размеру, а подходящие текстовые значения могут переводиться в `category`.

Это позволяет уменьшать размер DataFrame и экономить оперативную память при обработке больших наборов данных.

В логах можно отслеживать изменения потребления RAM во время обработки.

---

### 4. RFM-сегментация клиентов

На основании истории заказов выполняется сегментация клиентов по классической модели:

* **Recency** — насколько давно клиент совершал покупку;
* **Frequency** — насколько часто клиент покупал;
* **Monetary** — сколько клиент потратил.

На выходе формируются группы клиентов, например:

* VIP;
* активные клиенты;
* клиенты в зоне риска;
* спящие клиенты.

Это позволяет перейти от простой таблицы заказов к анализу **поведения клиентской базы**.

---

### 5. Поиск аномальных транзакций

Для каждой товарной категории выполняется статистический анализ стоимости заказов.

Проект использует **правило трех сигм**, позволяющее выделять значения, значительно отклоняющиеся от типичного поведения внутри категории.

Полученный результат можно использовать как основу для дальнейшей проверки подозрительных операций.

Важно: это демонстрация статистического метода обнаружения аномалий, а не полноценная промышленная antifraud-система.

---

### 6. Бизнес-визуализация

После обработки данных автоматически создаются графики.

Например, можно увидеть распределение выручки между клиентскими сегментами:

![Распределение выручки по сегментам](customer_segments_revenue.png)

А также количество обнаруженных аномалий по товарным категориям:

![Аномалии по категориям](detected_anomalies.png)

Визуализации позволяют быстро перейти от числовых результатов к понятной картине происходящего в данных.

## 📊 Какие результаты формируются

После выполнения pipeline создаются готовые артефакты.

### `report_by_categories.csv`

Сводная аналитика по товарным категориям:

* выручка;
* количество заказов;
* статистика аномалий;
* показатели, необходимые для дальнейшего анализа.

Файл сохраняется с кодировкой `utf-8-sig`, поэтому его удобно открывать в Excel.

### `report_by_segments.csv`

Отчет по клиентским сегментам, сформированным в результате RFM-анализа.

### `pipeline.log`

Журнал выполнения pipeline:

* этапы обработки;
* возникающие ошибки;
* результаты операций;
* информация об использовании памяти;
* диагностические сообщения.

## ⚙️ Установка

Создайте виртуальное окружение:

```bash
python -m venv .venv
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Windows:

```bash
.venv\Scripts\activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

---

## ▶️ Запуск

### Шаг 1. Создать исходные данные

```bash
python generator.py
```

### Шаг 2. Запустить полный pipeline

```bash
python main.py
```

После выполнения проекта будут сформированы аналитические отчеты, графики и лог обработки.

### Шаг 3. Запустить тесты

```bash
pytest test_pipeline.py
```
